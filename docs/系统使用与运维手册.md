## 1. 系统概述

企业内部设备全生命周期管理平台，支持资产录入/领用/退还/盘点/报废全流程、可视化看板、使用人设备数量排行、邮件提醒、LDAP 域账号集成与完整审计。

### 1.1 默认账号（首次部署由系统自动初始化）

| 用户名 | 初始密码 | 角色 | 权限 |
|--------|----------|------|------|
| `admin` | `admin123` | super_admin | 全部功能：用户管理、系统设置、审计日志、备份 |
| `zhangsan` | `123456` | admin | 资产管理、看板、发送提醒、使用人关联 |
| `lisi` | `123456` | user | 只读查看（可看看板与排行，不可管理） |

> ⚠️ 首次登录后请立即修改默认密码（右上角头像 → 修改密码）。

### 1.2 角色权限矩阵

| 功能 | super_admin | admin | user |
|------|:---:|:---:|:---:|
| 资产增删改查/导入导出 | ✅ | ✅ | ❌（只读） |
| 统计看板（排行/图表） | ✅ | ✅ | ✅ |
| 排行榜发送邮件提醒 / 使用人关联 | ✅ | ✅ | ❌（按钮不可见） |
| 部门 / 资产类型 / 资产状态 / 编号前缀管理 | ✅ | ✅ | ❌ |
| 用户管理（含 LDAP 同步） | ✅ | ❌ | ❌ |
| 审计日志 / 系统设置 / 备份恢复 | ✅ | ❌ | ❌ |

- **LDAP 用户**首次登录自动注册，默认角色由 `LDAP_DEFAULT_ROLE` 决定（通常 `user`），管理员可在用户管理中提权。
- **LDAP 账号受企业统一认证管理**：不能在系统内修改密码，管理员也不能重置（用户列表中有 `LDAP` 标识，重置按钮置灰）；所属部门等资料不受影响。

### 1.3 认证顺序（LDAP 权威模式）

```
登录请求 ──▶ LDAP 已启用？
              ├─ 是 ─▶ LDAP 认证（bind→搜索→用户密码验证）
              │        ├─ 成功 ─▶ 审计记「LDAP登录」，自动创建/同步本地账号（姓名/邮箱/密码）
              │        └─ 失败 ─▶ 回退本地认证 ─▶ 成功记「登录」/ 失败按锁定策略返回
              └─ 否 ─▶ 本地认证
```

## 2. Docker 镜像构建

```bash
cd /root/proj/tools/asset-manager-mc/v6.05
docker build -t asset-manager:6.06 .
```

- 多阶段构建：前端 `tsc + vite build` → 后端源码 → 运行镜像（Nginx + Node 18-alpine）
- 已配置 `.dockerignore`（排除 node_modules、dist、server/.env、.git 等），**不要删除**，否则宿主机损坏的 node_modules 会污染镜像
- 前后端都有 TypeScript 类型检查（构建时自动执行），构建失败先看类型错误
- 代码有改动时才需要重新构建；只重启用第 4 节脚本即可

## 3. LDAP 认证配置

### 3.1 配置文件

配置在 `server/.env`（参考 `server/.env.example`），当前生产环境的实际值：

```ini
LDAP_ENABLED=true
LDAP_URL=ldap://192.168.11.60:389
# 只读绑定账号（用于搜索用户）
LDAP_BIND_DN=uid=ldapreadonly,ou=THUWX,ou=People,dc=beijing,dc=tsinghua
LDAP_BIND_PASSWORD=******
# 搜索基址：支持多路径，用 | 分隔（DN 内含逗号，不能用逗号分隔！）
LDAP_SEARCH_BASE=ou=People,dc=beijing,dc=tsinghua
LDAP_SEARCH_FILTER=(uid={username})
LDAP_DEFAULT_ROLE=user
```

### 3.2 关键说明

| 项 | 说明 |
|----|------|
| 搜索过滤器 | OpenLDAP 用 `(uid={username})`；AD 域控才用 `(sAMAccountName={username})` |
| 多搜索基址 | `LDAP_SEARCH_BASE=ou=A,...|ou=B,...`，登录时依次查找、同步时合并去重；只拉取需要的 OU 可避免同步大量无关用户（`ou=People` 下可用 OU：THUWX/SPECIAL/RECONFIG/HRBUST/SEU/Group/Project/ProjectGroup/OUTSIDE/THUBJ/shixi/TU） |
| 自动注册 | LDAP 用户首次登录成功后自动创建本地账号（角色=`LDAP_DEFAULT_ROLE`），并同步姓名/邮箱/密码 |
| 同步范围 | 「从LDAP同步用户」按钮按基址分页拉取（每页 200，规避服务端条数限制），自动跳过只读绑定账号；**同步只增不删**，多余用户在用户管理中手动删除 |
| 配置生效 | `.env` 通过 `--env-file` 注入容器，**只在容器创建时读取**——改完必须 `docker rm -f` 后重新执行启动脚本 |

### 3.3 验证

```bash
curl -k https://localhost:8092/api/auth/ldap-status
# 返回 {"data":{"enabled":true}} 即生效
```

## 4. 部署运行容器

### 4.1 启动脚本 `start_v6.06_ldap.sh`

```bash
docker run -d \
  --name asset-manager-v6.06 \
  --network host \
  -v /opt/asset-manager/data:/app/server/data \
  --env-file /root/proj/tools/asset-manager-mc/v6.05/server/.env \
  -e JWT_SECRET=***REMOVED*** \
  -e PORT=8092 \
  --restart unless-stopped \
  asset-manager:6.06
```

| 参数 | 说明 |
|------|------|
| `--network host` | 宿主机网络模式，Nginx 监听 `PORT`（8092，HTTPS 自签证书），后端 API 默认 3001（不对外，可通过 `-e API_PORT` 调整，见 8.9） |
| `-v /opt/asset-manager/data:/app/server/data` | 数据卷：SQLite 数据库、上传的 Logo、HTTPS 证书 |
| `--env-file` | 注入 LDAP 等配置（优先级低于 `-e`） |
| `-e JWT_SECRET` | 生产必须改掉默认值 |
| 访问地址 | `https://<服务器IP>:8092`（自签证书需在浏览器信任） |

### 4.2 常用运维命令

```bash
docker logs -f asset-manager-v6.06          # 查看日志（含 [Migration]/[LDAP]/[AuditLog]）
docker restart asset-manager-v6.06          # 重启
docker rm -f asset-manager-v6.06 && bash start_v6.06_ldap.sh   # 重建（改过 .env/镜像后必须这样做）
```

> ⚠️ 改 `.env` 或更新镜像后，`docker restart` 不会生效，必须删除容器重建。

### 4.3 环境变量一览（server/.env）

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `JWT_SECRET` | dev-secret-key | 生产必须修改 |
| `DB_PATH` | ./data/asset-manager.db | 数据库文件路径 |
| `LDAP_ENABLED` | false | 是否启用 LDAP |
| `LDAP_URL` / `LDAP_BIND_DN` / `LDAP_BIND_PASSWORD` | — | LDAP 服务器与只读绑定账号 |
| `LDAP_SEARCH_BASE` | — | 搜索基址，多路径用 `\|` 分隔 |
| `LDAP_SEARCH_FILTER` | (uid={username}) | 登录名过滤器 |
| `LDAP_DEFAULT_ROLE` | user | 自动注册的默认角色 |

## 5. 使用指导

### 5.1 统计看板

- **顶部状态统计卡片（动态）**：卡片来自「资产状态管理」中定义的全部状态（每个状态一张，含数量为 0 的），名称/颜色/顺序跟随状态管理配置，**全部可点击**跳转到对应状态的资产列表；新增状态自动出现卡片，无需改代码。**资产总数**卡片在最左，点击查看全部资产
  - 状态超过 8 个时默认折叠（只显示前 8 个，按状态管理的自定义排序），下方出现“展开全部 N 个状态 / 收起”按钮
  - 状态顺序可在「资产状态管理」中用上移/下移调整，全局生效（看板卡片、资产表单下拉、筛选、盘点）
- **使用人设备数量排行**：
  - 每页 20 条可翻页/跳页，支持按使用人搜索（顶栏全局搜索联动）
  - 列：排名（前三名彩色徽章）｜使用人｜邮箱（管理员见全邮箱，普通用户见打码）｜设备数量｜设备类型
  - 点击**使用人名或设备数量** → 跳转资产列表并按该使用人精确筛选
  - **发送提醒**：给设备过多的人发邮件（见 5.6）；“关联”按钮可为未关联的使用人绑定登录用户；“无邮箱”（置灰）表示需先去用户管理补邮箱
  - **使用人数上限**：单次最多拉取 **1000** 个使用人（前端分页展示全部，页码跳转超范围会提示）
    - 调整方法：修改 `src/components/Dashboard.tsx` 中的 `RANKING_FETCH_LIMIT` 常量（如改为 `3000`），重新构建镜像并重建容器
    - 注意后端另有硬上限 5000（`server/src/routes/dashboard.ts`），前端调大超过 5000 时需同步修改
    - 调大影响：前端内存略增（每条约几十字节）、后端查询耗时按行数线性微增，数千级规模无可感知差异；建议使用人数接近 900 时再调整
- **部门资产分布**：点击柱条跳转该部门资产列表
- **近期变动记录**：全部变动记录，支持分页（每页 10/20/50 条、页码跳转）

### 5.2 资产管理

- 筛选：关键词（名称/编号/使用人/MAC/主机名/备注）、类型、部门、状态、位置，支持排序
- 从看板跳转过来时，工具栏会显示蓝色 `使用人: xxx` / 绿色 `部门: xxx` / 橙色 `状态: xxx` 标签，点 × 清除
- **使用人填写（重要）**：优先从下拉中选择（显示中文名+登录名），系统会同时记录“使用人中文名”和“归属登录账号”——这是发邮件提醒的关联依据；无账号人员可直接手输
- 资产编号：选部门后自动按前缀配置生成（预览格式见表单提示）；也可手动指定

### 5.3 资产编号前缀规则（系统设置）

| 配置 | 说明 |
|------|------|
| 部门**填写** | 该部门新增资产时使用此前缀 |
| 部门**留空** | **全局默认前缀**：所有未匹配到专用配置的部门使用它 |
| 序号生成 | 在配置的位数内递增，遇已占用编号自动跳过 |

> 编号规则格式：`前缀 + 后缀 + 序号（按位数补零）`，例：`MC-IT` + `2604` + 3 位 → `MC-IT2604001`

### 5.4 导入 / 导出

- **导出**：Excel 与 CSV 字段完全一致（16 列），包含资产编号、名称、类型、型号、使用部门、使用人、**归属用户**、购入日期、状态、位置、**有线MAC、无线MAC、主机名**（多值用 `;` 分隔）、备注、创建/更新时间
- **导入**：支持全部 16 列；MAC/主机名按 `;`（或逗号、空格）拆分；“归属用户”留空时**按使用人姓名自动匹配登录账号**（中文姓名 → 真实姓名 → 用户名）
- 导出动作会写入审计日志（记录操作人、格式、条数）

### 5.5 用户管理

- 搜索（用户名/姓名/邮箱）+ 分页（每页 10/20/50/100，支持页码跳转）
- 从 LDAP 同步用户（见 3.2）；**手动关联**：排行榜里也可以直接做
- **中文姓名**：用于与资产登记的使用人关联，本地维护，LDAP 同步不会覆盖
- **邮箱**：LDAP 登录时若目录中有 `mail` 会自动同步/覆盖（目录无邮箱的手动填写不受影响）；发送邮件提醒依赖此字段
- LDAP 账号显示紫色 `LDAP` 标签；密码修改/重置对 LDAP 账号禁用

### 5.6 邮件提醒（SMTP）

1. 系统设置 → 邮件通知（SMTP）：填服务器/端口/SSL/账号/密码/发件人显示名称，保存后点“发送测试邮件”验证
2. 看板排行榜 → 点“发送提醒” → 弹窗确认收件人邮箱与设备清单（编号/名称/类型）→ 发送
3. 邮件内容含使用人姓名、设备总数、明细表格；每次发送写审计日志与 `mail_logs`（弹窗中会提示上次提醒时间，设备数无变化时会提醒）
4. 仅手动触发，无自动扫描

### 5.7 部门 / 资产类型 / 资产状态扩展

- 新增后**立即生效**：资产表单的类型/状态/部门下拉每次打开都实时拉取；看板自动识别新状态及颜色，并自动出现对应的可点击统计卡片（状态多于 8 个时折叠展示）
- **资产状态支持自定义排序**：在资产状态管理中通过上移/下移调整顺序，看板卡片、资产表单下拉、筛选、盘点等全局跟随
- 删除保护：删除部门时可转移其名下资产；删除状态后存量资产保留原状态值（看板以灰色兜底显示）
- 新部门未配置编号前缀时自动使用全局默认前缀

### 5.8 备份与恢复（系统设置）

- **导出备份**：完整 SQLite 数据库文件，包含资产、用户（含中文姓名/邮箱/关联字段）、类型/状态/部门、前缀配置、**SMTP 配置（含明文密码，请妥善保管）**、审计/变动/盘点/邮件记录
- **不包含**：① LDAP 连接配置（在宿主机 `server/.env`）② 企业 Logo 图片（在数据卷 `uploads/` 目录）③ HTTPS 证书（会自动重新生成）
- **恢复**：上传备份文件即整体还原；旧版本备份恢复到新版会自动补齐缺失列（自动迁移）

### 5.9 审计日志

- 记录所有关键操作（27+ 种类型且自动扩展）：登录/登出（含 LDAP）、资产增删改/导入/**导出**、用户/部门/类型/状态/前缀管理、备份、邮件提醒、使用人关联、LDAP 同步等
- 筛选：操作类型（动态下拉，按出现频次排序）/ 用户名 / 日期区间
- 自动清理：启用后每天凌晨 3 点（及容器启动时）删除超过保留天数的日志；**保留天数强制 30~3650 天**；清理为硬删除，建议保留天数别设太短

## 6. 数据模型要点

### 6.1 “使用人关联体系”（发邮件提醒的基础）

| 字段 | 位置 | 含义 | 维护方式 |
|------|------|------|----------|
| 使用人 `user` | assets 表 | 设备登记的中文名（给人看） | 表单下拉（写入中文名）或手输 |
| 归属用户 `owner_username` | assets 表 | 精确关联的登录账号（系统内部用） | 表单下拉选中时自动写入；排行榜“关联”按钮批量写入；导入自动匹配 |
| 中文姓名 `cn_name` | users 表 | 用户对应的常用中文名 | 用户管理手动维护；LDAP 同步**不会覆盖** |

**邮箱匹配优先级**（发提醒时）：

```
assets.owner_username（精确） → users.cn_name → users.real_name → users.username
```

**认证来源 `auth_source`**（users 表）：`ldap` / `local`，LDAP 认证通过时自动标记，用于禁用 LDAP 账号的本地改密。

### 6.2 使用人 ≠ 登录用户

资产“使用人”是与登录账号无关的自由文本（实际登记多为中文姓名）；关联通过上面的匹配链完成。排行榜中“关联”按钮就是为无法自动匹配的使用人手动指定登录用户。

## 7. 常见问题 FAQ

### Q1：为什么删除资产后，下一个编号不复用已腾出的号？

**建议不复用，这是刻意设计**：资产编号是设备的“身份标识”而非计数器。编号会出现在变动记录、审计日志、提醒邮件、导出文件甚至设备标签上；如果复用，历史记录将无法区分新旧设备（例：某编号 3 月报废、6 月被新设备复用，翻旧记录就产生歧义）。正常流程资产报废用“报废”状态而非删除；录错时删除留下的跳号无害——资产数量统计用的是 `COUNT(*)`，与编号大小无关。

### Q2：备份文件里有什么？缺什么？

包含数据库全部内容（见 5.8）。**不含** LDAP 配置（`server/.env`）、企业 Logo 图片（数据卷 `uploads/`）。迁移环境时：备份 .db + `server/.env` + 启动脚本 + uploads 目录，四样齐了就是完整状态。

### Q3：使用人和归属用户是什么关系？

见第 6 节。简言之：使用人是给人看的中文名，归属用户是系统找邮箱用的登录账号，两者在表单下拉选中用户时同时写入。

### Q4：登录后提示“网络连接失败，请检查网络”但能正常操作？

该提示仅在**请求完全得不到响应**（服务重启窗口/网络瞬断/30 秒超时）时出现。已优化：GET 请求会自动静默重试一次，成功则无感知。若非维护窗口频繁出现，再排查网络链路（WiFi/交换机）。

### Q5：新增部门后，另一台电脑的新增资产里看不到？

旧版本会（部门列表缓存到登录会话）；**v6.06 已修复**——资产表单的类型/状态/部门/使用人选项每次打开都实时拉取。若仍遇到，先确认浏览器已强刷（Ctrl+Shift+R）。

### Q6：LDAP 用户为什么不能改密码？

LDAP 权威模式下，密码由企业域控统一管理（系统内改密/管理员重置都会被拒绝），避免本地密码与域密码分叉导致认证来源混乱。

### Q7：排行榜里“无邮箱”置灰怎么处理？

说明使用人已关联到登录用户但该用户没有邮箱：到用户管理补全邮箱即可。显示“关联”则说明还没关联到任何用户，点击后选择对应用户一键完成。

### Q8：同步了很多不需要的 LDAP 用户怎么办？

缩小 `LDAP_SEARCH_BASE`（多路径只写需要的 OU）后重建容器，再点一次同步；多余用户在用户管理删除（同步只增不删，删了不会被重新加回来，除非再次同步且该用户仍在搜索范围内）。

## 8. 异常问题排错手册

### 8.1 LDAP 登录报“用户名或密码错误”

排查顺序：

1. `curl -k https://localhost:8092/api/auth/ldap-status` 确认 `enabled:true`（false 说明 `.env` 没生效或没重建容器）
2. 容器内测试连通：`ping <LDAP_IP>` / 端口 389 是否通
3. 查看 `docker logs` 中的 `[LDAP]` 前缀日志（bind 失败/搜索失败/密码错误分三类）
4. 本地账号不受影响；注意本地同名账号密码优先生效的历史遗留情况已通过 LDAP 优先模式消除

### 8.2 LDAP 连接 EHOSTUNREACH（网络不可达）

**典型案例**：Docker 会为每个 compose 项目创建 bridge 网络（如 192.168.0.0/20），若与业务网段重叠，宿主机发往该网段（如 LDAP 192.168.11.60）的流量会被路由进死桥。

```bash
ip route                       # 看 192.168.x.x 是否被 br-xxx 网络占用
docker network ls              # 找到占用网段的空闲网络
docker network rm <网络名>      # 无容器使用时删除
```

长期方案：`/etc/docker/daemon.json` 配置 `default-address-pools` 避开业务网段。

### 8.3 `ldap-status` 显示 enabled:false 但 .env 写了 true

老版本代码缺陷：ESM import 提升导致 `dotenv` 在配置读取之后才加载。**v6.06 已修复**（`import 'dotenv/config'`）。确认镜像为本地构建的 `asset-manager:6.06`，且容器用 `--env-file` 方式重建过。

### 8.4 LDAP 同步报 "Size Limit Exceeded"

LDAP 服务器对单次搜索有条数限制。系统已使用分页搜索（每页 200）规避；若仍出现，检查 LDAP 服务端 `olcSizeLimit` 配置。

### 8.5 登录提示“用户名或密码错误”但密码正确

连续失败 5 次会触发账号锁定（约 15 分钟自动解锁），或让管理员删除 `login_locks` 表中对应记录；LDAP 用户可稍后重试（LDAP 认证成功会自动清除锁定）。

### 8.6 管理员密码遗失

超级管理员可重置其他用户密码；若 `admin` 本身密码遗失，需在服务器上重置：

```bash
docker exec -w /app/server asset-manager-v6.06 node -e "
const bcrypt = require('bcryptjs');
const initSqlJs = require('sql.js');
const fs = require('fs');
Promise.all([bcrypt.hash('新密码', 10), initSqlJs()]).then(([hash, SQL]) => {
  const db = new SQL.Database(fs.readFileSync('./data/asset-manager.db'));
  db.run('UPDATE users SET password = ? WHERE username = ?', [hash, 'admin']);
  fs.writeFileSync('./data/asset-manager.db', Buffer.from(db.export()));
  console.log('done');
});"
docker restart asset-manager-v6.06
```

### 8.7 页面显示异常/功能没更新

浏览器缓存了旧版前端文件：`Ctrl + Shift + R` 强制刷新。

### 8.8 容器起不来 / 数据库报错

1. `docker logs asset-manager-v6.06` 看具体报错
2. 数据卷权限：确认 `/opt/asset-manager/data` 可写
3. 数据库损坏时可用最近一次导出的备份恢复（见 5.8）

### 8.9 端口占用（8092 / 3001）

先查谁占用了端口：

```bash
ss -tlnp | grep -E ':8092|:3001'      # 查看端口占用进程
docker ps                              # 确认是否被本系统其他容器占用
```

**情况一：外部端口 8092（Nginx）被占** —— 换端口即可：

1. 编辑 `start_v6.06_ldap.sh`，把 `-e PORT=8092` 改为新端口（如 `-e PORT=8443`）
2. 重建容器：`docker rm -f asset-manager-v6.06 && bash start_v6.06_ldap.sh`
3. 访问地址变为 `https://<IP>:8443`（自签证书需重新信任）

**情况二：后端端口 3001（API）被占** —— 两种处理方式：

- **推荐：释放 3001**。`ss -tlnp | grep :3001` 找到占用进程并停掉它
- **或改用其他端口**（v6.06 起支持）：在启动脚本中加一行 `-e API_PORT=3101`，然后重建容器。后端监听端口与 Nginx 转发目标会自动同步为新端口，前端页面无需任何改动

> 注意：`--network host` 模式下这两个端口直接占用宿主机，与 `-p` 端口映射无关；浏览器访问的永远是 `PORT`，`API_PORT` 仅容器内部使用。

**情况三：端口处于 TIME_WAIT 状态导致容器启动失败** —— 通常是刚重启过容器，等待 30~60 秒再执行启动脚本即可。

## 9. 升级与迁移清单

### 9.1 日常升级（同机更新版本）

```bash
cd /root/proj/tools/asset-manager-mc/v6.05
docker build -t asset-manager:6.06 .        # 1. 构建新镜像
docker rm -f asset-manager-v6.06            # 2. 删除旧容器
bash start_v6.06_ldap.sh                    # 3. 用新镜像重建
```

数据卷独立于容器，升级不影响数据；启动时自动执行数据库迁移（缺的列自动补齐）。

### 9.2 迁移到新服务器

1. 新服务器装 Docker，构建/导入镜像（`docker save/load`）
2. 迁移四样东西：备份的 `.db` 文件（或直接拷贝 `/opt/asset-manager/data`）、`server/.env`、`start_v6.06_ldap.sh`、`uploads/` 目录（Logo）
3. 新机执行启动脚本，浏览器访问验证

### 9.3 数据安全

- 定期在系统设置导出备份（含 SMTP 明文密码，注意保管）
- 生产环境务必修改 `JWT_SECRET` 与默认密码
- 审计日志清理为硬删除，保留天数建议 ≥180
